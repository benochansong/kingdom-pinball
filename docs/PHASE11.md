# PHASE 11 — 오류 수정·UI 정리·출시 평가

2026-11-27 · 0.11.0-beta.1. 실제 코드 수정과 검사 결과입니다. 자동 모델 검사, 개발용 분리 저장 검증실, 일반 브라우저 플레이를 구분합니다. 공개 배포나 DNS 변경은 하지 않았습니다.

## 1. 재발사 오류의 실제 원인

- 왕국/전쟁의 마지막 공 손실은 `launchState=awaiting`과 `state=relaunch`로 전환되지만, 에너지 지불·새 Matter body 생성이 수동 UI 경로에만 연결되어 있었습니다. 자동 준비를 기대하는 플레이어에게 공 없는 상태가 지속됐습니다.
- 샌드박스 및 로그라이크의 공 보존 경로는 실제 새 공을 만들면서 경제 상태를 `inflight`로 남겼습니다. 다음 Space 입력에서 `beginLaunch()`가 거절되어 정지된 새 공을 발사할 수 없었습니다.
- 멀티볼 만료와 대표 공 손실이 같은 step에 일어나면 살아 있는 보조 공까지 지울 수 있었습니다. 온라인의 테이블 이탈 복구도 `spawn()`으로 전체 공을 교체해 남은 멀티볼을 잃을 수 있었습니다.
- 클래식의 기존 기본 재생성은 별도 경로였습니다. 클래식에서도 항상 첫 공 뒤 멈춘다는 현상을 독립적으로 재현했다고 주장하지 않습니다.

수정 전 분리된 전쟁 체크포인트에서 에너지 회복 후에도 공 0개/재발사 대기 상태가 남는 것을 UI로 관찰했습니다. 이 재현은 제어된 체크포인트였으며 자연 아웃 전체의 증거는 아닙니다.

## 2. 수정 방식

공 손실 → 기존 모드의 비용/목숨 규칙 → 게임 시간 800ms 대기 → 에너지 한 번 지불 → 실제 Matter body 생성 → 입력/틸트/복구 상태 초기화 → 발사 준비 순서를 공통 상태 관리자에서 처리합니다. 일시정지 중에는 대기 시간도 멈춥니다. 자원 부족은 기존 충전/원정 종료 규칙을 유지합니다. 클래식은 계속 5개 공입니다.

공이 없는데 정상 재생성 예약도 없는 상태를 500ms 관찰하면 정상 손실 규칙으로 복구합니다. 이미 지불된 `ready` 상태만 무료 복원합니다. 남아 있는 공을 복제하지 않습니다. 온라인 두 좌석도 서버가 재생성·비용·손실 횟수를 결정합니다.

## 3. 연속 재발사 결과

- 자동 검사: 클래식 5개 공 × 3회 재시작, body ID 교체·월드 제거·최종 기록 1회 저장.
- 자동 검사: 왕국/전쟁 각각 에너지 100→80→60→40→20→0, 부족 시 충전 후 발사, 대기 중 일시정지, 모드 전환, 체크포인트 복원, 비정상 body 소실.
- 실제 브라우저: Space 입력 → 실제 공을 아웃 영역으로 이동시키는 DEV 버튼 → 정상 물리 update의 손실 판정. 클래식 5개 소진과 결과 창, 다시 시작 후 Space/A 입력 성공. 왕국 전쟁에서 2회 손실 후 80/60 에너지의 새 공과 세 번째 실제 발사 확인. 샌드박스도 새 공 발사와 플리퍼 입력 확인.
- 브라우저 기록 예: 전쟁 1,050ms drain → 1,864ms paid respawn, 9,830ms drain → 10,645ms paid respawn. 실제 프레임 간격 때문에 800ms에 프레임 오차가 더해집니다.

DEV 아웃 버튼은 상태를 성공으로 덮어쓰지 않고 실제 Matter 공 위치를 이동합니다. 이것은 반복 가능한 손실 경로 검사이며 장시간 자연 플레이의 난이도 평가를 대체하지 않습니다.

## 4. 멀티볼 손실

3/7/10개 동시 손실에서 재발사 공 1개·손실 1회·에너지 20 한 번 차감, 만료와 대표 공 아웃 동시 발생 시 살아 있는 공 승계, 온라인 대표 공 테이블 이탈 시 남은 2개 유지가 회귀 검사에 포함됩니다. 기존 마법 검사는 STORM 구조 5회 상한과 10개 body 상한도 확인합니다. 모든 공 손실 뒤 다시 발사하는 assertion이 있습니다.

## 5. UI 줄바꿈 원인

좁은 고정 메뉴 열에 길이가 다른 한글/영어를 하나의 라벨로 넣고 작은 버튼 높이·내부 flex 축소를 적용했습니다. 화면별 CSS가 달라 한국어가 문자 단위로 쪼개지고 부가 영어가 주요 라벨 공간을 차지했습니다. 단순한 전체 `nowrap`은 긴 설명을 화면 밖으로 밀어내므로 적용하지 않았습니다.

## 6. 공통 UI 수정

메뉴 버튼을 한글 주 라벨과 작은 영어 보조 라벨로 분리했습니다. 내용 폭을 측정해 공간이 부족하면 영어 보조만 숨깁니다. 한국어 라벨을 강제로 축소하지 않습니다. 버튼 최소 높이 44px, 메인 버튼 50px/주요 버튼 56px, 일관된 간격·패딩·단어 단위 줄바꿈, 모달/설정/명령 행의 자연스러운 재배치를 적용했습니다. 설명은 여러 줄을 허용합니다. 접기 섹션은 네이티브 details/summary를 사용합니다.

## 7. 수정·검사한 화면

주요 플레이 / 게임 모드 / 플레이어·기록 / 도움말·관리로 메인을 정리했습니다. 공통 스타일은 경제·건설·군대·전쟁·마법·캠페인·온라인에 적용됩니다. 실제로 캠페인 슬롯·생성·월드맵·연구, 모드 허브, 생산시설, 군대 생산, 마법 편성, 건설 도구, 온라인 경기 화면을 열었습니다. 390px에서 문서/모달 가로 넘침과 버튼 내부 잘림 DOM 검사를 수행했습니다. 작은 마법 편성 선택창은 한 열로 변경했습니다. 모든 가능한 팝업 조합을 전수 캡처한 것은 아닙니다.

## 8. 한글·영어

설정에 한국어 / English / 한국어+English를 추가하고 저장 이행 시 기본값을 병기로 둡니다. 주요 메뉴의 한국어·영어·aria 라벨을 함께 관리하며 주요 설정·명령·자원·조작 문구와 접근성 속성을 공통 카탈로그에서 변환합니다. 동적으로 생성되는 UI도 반영합니다. **캠페인 상세 서사·일부 동적 문장은 아직 한국어입니다.** 설정에 부분 지원 안내를 표시했습니다. 완전한 영문판 출시로 평가하지 않습니다.

## 10. 추가 수정

재생성 대기 중 일시정지/관리창 복귀 후 잘못된 수동 충전창이 열리던 경로, 게임 오버 후 계속 예약되던 음악/환경음, 온라인 대표 공 복구 시 멀티볼 소실, 온라인 진행 중의 잘못된 발사 안내를 수정했습니다. `.gitignore`의 광범위한 `data/`를 루트 `/data/`로 제한해 새 소스 데이터 파일이 누락되지 않게 했습니다.

## 11. 게임 플레이 개선

자동 새 공 준비와 실제 발사 상태 안내가 중단된 것처럼 보이는 구간을 줄입니다. 공 상태 로그는 80개로 제한하고 디버그 설정에서만 표시합니다. DEV 검사 버튼은 프로덕션에서 제외합니다. 공과 병력의 정밀 교차 계산 전에 정확한 사각 범위로 먼 병력을 제외하며, 병력 순서·두 타격 상한·실제 판정 거리는 유지합니다.

## 12. 경제·전쟁 밸런스

생산량·건설비·병력 능력치·보상·AI 경제를 근거 없이 변경하지 않았습니다. 재발사 대기만 0.8초로 통일했습니다. 코어 에너지 비용 20, 클래식 5개, 온라인 에너지 부족 시 추가 15초 긴급 복구는 유지합니다. 자동 결제 안내를 실제 규칙과 맞췄습니다. 모든 난이도의 초반 5/10/20분 수동 플레이·승률 분석은 미완료이므로 최종 밸런스 인증을 하지 않습니다.

## 13. 초보자 편의

현재 목표 영역에서 발사 준비 / 충전 중 / 새 공 준비 / 에너지 회복 필요를 우선 안내합니다. 기존 단계별 튜토리얼과 기본·군사·마법 연습은 유지하고 메인 도움말에서 찾기 쉽게 정리했습니다. 새 왕국의 기존 해금·자원은 보호했습니다.

## 14. 캠페인

기존 회귀 묶음은 8지역 24스테이지 목표 경로, 월드 코어 결합, 별도 NG+, 보스 단계, 포털 안전성, 중복 보상, 저장 충돌을 검사합니다. 실제 UI에서는 새 슬롯·월드맵·잠긴 단계·연구를 확인했습니다. 모델 검사는 생산/피해 등 제어된 입력을 사용합니다. 24개 스테이지를 모두 키보드로 처음부터 끝까지 재완주했다는 의미는 아닙니다.

## 16. 저장·불러오기

기존 버전의 점수·음량·캠페인/왕국 저장을 유지하며 언어만 기본값으로 보충합니다. 신규 검사는 손실 대기 체크포인트를 다시 열 때 추가 무료 공이나 중복 비용이 생기지 않는지 확인합니다. 기존 저장 손상·차단된 localStorage·오래된 탭의 쓰기 충돌·결과/보상 중복 방지 검사를 유지했습니다. 브라우저 UI 검증은 분리된 세션 저장을 사용했습니다. 대용량 사용자 저장을 실제로 가져와 검증한 것은 아닙니다.

## 17. 온라인

실제 로컬 서버의 서로 다른 게스트 2명으로 코드 입장·준비·키보드/화면 발사, A 유효 타격 6회/B 5회와 실제 자원 증가를 확인했습니다. B 새로고침 후 같은 방과 목재360/마력석87을 복원했습니다. 92초 경기의 항복 뒤 양쪽에 같은 경기 ID의 DEFEAT/VICTORY를 확인했고 콘솔 오류는 없었습니다. 390px 온라인 화면의 버튼 잘림과 문서 가로 넘침은 없었습니다.

서버 모델에서는 두 좌석 각각 3회 연속 실제 body 아웃 및 비정상 body 소실, 한 번만 차감되는 에너지, 0에너지 긴급 복구, 대표 공 이탈 시 멀티볼 보존을 확인합니다. 실제 소켓 검사에는 입력 재전송 거부·재접속·결과 중복 저장 방지가 포함됩니다. 이번 브라우저 경기에서 0.8초 자연 아웃→재생성의 전체 순간을 직접 관찰했다고 주장하지 않습니다. WAN·다른 PC·패킷 손실·공개 인증 운영은 미검증입니다.

## 19. 주요 파일

`src/core/GameStateManager.ts`, `src/magic/BallManager.ts`, `server/simulation.ts`가 공 수명을 수정합니다. `src/ui/ReleaseUI.ts`, `src/release.css`, `src/data/localization.ts`, `src/ui/PresentationUI.ts`가 공통 UI/언어/안내를 담당합니다. `tests/lifecycle.test.ts`, 온라인·사운드·설정 검사와 `src/dev/ReleaseLab.ts`가 재현을 보조합니다. `public/THIRD_PARTY_NOTICES.txt`에 Phaser/Matter.js/ws의 설치된 라이선스 원문을 동봉합니다.

## 20. 설치·프로덕션 빌드

오프라인 캐시를 사용한 `npm install --ignore-scripts --offline --no-audit --no-fund`가 성공했습니다. 최종 전체 테스트·빌드·산출물 브라우저 실행 결과는 이 문서의 최종 검사 기록에 적습니다. 빌드 산출물은 `dist/`, 서버는 `dist-server/index.js`입니다. 스크립트 실행을 생략한 설치 검사가 새로운 환경의 온라인 다운로드까지 검증한 것은 아닙니다.

## 21. 미해결·제한

높은 우선순위: 150기+STORM 성능, 최종 앱 내 브라우저의 저속 프레임 현상 원인 확인, 실제 장시간 렌더/메모리 안정성, 전체 난이도 수동 검수. 보통 우선순위: 부분 영어, 모든 모달·화면 확대·OS 배율 조합, 실제 모바일 입력. 온라인 별도: 공개 계정/랭크, 서버 재시작 경기 복원, 나머지 협동 보스, 공용 서비스 보안·운영·부하 평가. 개발용 SQLite 경고는 런타임의 experimental 경고이며 브라우저 오류와 구분합니다.

## 22. 싱글 플레이 출시 판단

핵심 오류가 수정된 **로컬 베타 검수 버전**입니다. 최종 앱 내 브라우저에서 아래 저속 진행을 관찰했으므로 일반 브라우저의 정상 속도 재확인 전 배포 권장은 보류합니다. 고부하 성능과 전체 수동 캠페인 검수도 남아 정식 출시 완료로 선언하지 않습니다.

## 23. 온라인 출시 판단

로컬·신뢰 가능한 소규모 환경에서 검증하는 **온라인 베타**입니다. 공개 운영 준비 완료가 아닙니다. 기본 서버 방 상한 5개를 유지합니다. 정적 싱글 플레이는 온라인 서버 설정 없이 실행할 수 있습니다.

## 24. 사용자 직접 확인 권장

자신의 PC에서 자연 아웃을 여러 번 반복하고 실제 조작감을 확인하세요. 실제 저장으로 이어하기, 창/전체 화면, 브라우저 확대 80–200%, OS 배율, 한/영 입력 환경, 낮은 그래픽 품질과 고부하 전투를 확인해야 합니다. 온라인 공개 전에는 다른 PC/네트워크, 장시간 연결·재접속·서버 장애·로그/백업 운영도 검사해야 합니다. 이번에 실행하지 않은 항목은 성공 체크로 바꾸지 않았습니다.

## 25. 실행

프로젝트 폴더에서 `npm install` → `npm run dev`, 터미널의 URL을 여세요. 온라인 개발은 `npm run multiplayer:dev`, 프로덕션 클라이언트 확인은 `npm run build` → `npm run preview -- --port 5177`입니다. 자세한 순서와 저장/환경 변수는 [RELEASE_GUIDE](../RELEASE_GUIDE.md), [MULTIPLAYER_GUIDE](../MULTIPLAYER_GUIDE.md)에 있습니다.

## 최종 검사 기록

- `npm test`: 20개 파일, **256개 통과**, 별도 생성/soak 2개는 기본 실행에서 제외. SQLite experimental 경고만 출력됐습니다. 이후 진단용 frame/time/update-count 필드만 추가했고 코어/수명 검사를 다시 실행했습니다.
- `npm run build`: TypeScript와 Vite 성공. CSS 60.61kB, 게임 JS 582.35kB, Matter 84.30kB, Phaser 1,208.18kB(압축 전). DEV 공 이동/검증실 문자열은 배포 JS에 없고 `THIRD_PARTY_NOTICES.txt`가 포함됐습니다.
- `npm run server:build`: TypeScript/esbuild 성공. 별도 로컬 포트·메모리 DB로 빌드 서버를 실행해 `/health`의 `status: ok` 확인. `kingdom-10.1`은 호환 프로토콜 식별자이며 패키지 릴리스 버전과 다릅니다.
- 실제 `dist`를 5177 포트에서 열어 메인·설정·클래식 발사/플리퍼·일시정지/메뉴 복귀를 확인했습니다. 콘솔 오류는 없었습니다. 다만 마지막 실행에서는 **앱 내 브라우저의 게임 시간이 매우 느리게 전진**했습니다. 표시된 프레임 delta는 약16.67ms인데 update 호출 수는 낮았고, 같은 브라우저에서 개발 서버를 새로 열어도 같은 현상을 관찰했습니다. 따라서 배포 빌드만의 오류로 단정하지 않습니다. 정상 프레임 속도로 실행된 앞선 9종 표본과 구분하며, 이 마지막 환경의 정상 속도는 미확인입니다. 원인을 확정하지 못했으므로 일반 Chrome/Edge에서도 확인해야 할 높은 우선순위 항목으로 남깁니다.

- 브라우저 탭 5177을 사용자 확인용으로 열어 두었습니다. 공개 서버 배포·도메인·DNS·유료 서비스는 변경하지 않았습니다.
