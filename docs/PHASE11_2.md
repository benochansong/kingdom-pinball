# PHASE 11.2 — ROYAL RESCUE CANNON

검증일 2026-11-27 · 0.11.2-beta.1

## 1. 기존 원형 범퍼 제거
`outlane-guard` 2개(중심 110/466,781, 반지름 18)와 반발 보정을 제거했다. 런타임 재충전형 킥백도 제거했다. 기존 저장용 필드와 건설 금지 영역은 호환성을 위해 유지한다. 기존 건물을 삭제·이동하지 않는다. Matter 엔진·플리퍼·슬링·발사·게이트 보정은 유지한다.

## 2. 왼쪽 대포
위험 영역 x65~154, y750~829에서 내려오는 주 공을 포착한다. 중앙으로 돌아오는 공, 상승 중인 공, 가이드 안쪽의 정상 경로는 제외한다. 포구 (210,722)에서 우상향으로 발사한다.

## 3. 오른쪽 대포
위험 영역 x422~518, y750~829에 같은 규칙을 적용한다. 포구 (366,722)에서 좌상향으로 발사한다. 초기 약 50도 설정의 부족한 플리퍼 접근을 측정해 최종 **좌우 대칭 54도·1,000px/s**로 조정했다.

## 4. 포착·발사 물리
`IN_PLAY → RESCUE_DETECTED → RESCUE_CAPTURED → RESCUE_CHARGING → RESCUE_LAUNCHING → IN_PLAY` 상태 머신이다. 포착 이동 100ms, 충전 300ms 동안 같은 Matter body를 static/sensor 및 mask 0으로 보관한다. held 공은 충돌·전투 궤적·지역 힘·끼임 복구·아웃·특수 공 변환에서 제외한다. 발사 때 원래 질량·마찰·충돌 상태를 복원하고 같은 ID/객체에 속도를 준다. 새 공 생성이나 에너지 차감은 없다.

## 5. 중앙 복귀 경로
포구와 진행 방향 40px를 벽·시설·공·현재 플리퍼와 대조한다. 막히면 포착하지 않거나 충전을 취소하고 원래 위치·속도로 돌려준다. 기존 건물을 강제 이동하지 않는다. 2초 재발동 제한과 중앙 x165~411, y<675 실제 이탈 조건을 함께 사용한다. 포신과 화살표는 실제 발사 벡터를 사용한다.

[측정 스크립트](../scripts/rescue-cannon-balance.ts): `node --import tsx scripts/rescue-cannon-balance.ts`. [원자료](RESCUE_MEASUREMENTS.json): 240Hz Matter, 클래식·왕국·전쟁 × 좌우 × 구조 켬/끔 × 진입 조건 20개 = **240회**. 구조 켠 **120회 모두 중앙 복귀와 실제 플리퍼 접촉**, 발사 후 0.3초 내 아웃 0건, 객체 증가 0건. 구조 끔은 같은 위험 위치에서 약 0.32~0.33초 후 아웃했다.

구조 켬에서 전쟁 왼쪽 20회는 평균 5.27초 후 아웃, 나머지 100회는 30초 관측 상한에 도달했다. **30초는 평균 생존 시간 확정값이 아니다.** 단순 반응형 플리퍼와 기본 목표물을 사용하며 BALL SAVE·경제·전투·끼임 복구는 실행하지 않는 물리 경로 실험이다. 포착 후 고정 출구/속도로 초기화되므로 서로 다른 진입 조건도 이후 경로는 수렴한다. 사람 실력별 생존 시간이나 장기 밸런스 표본으로 해석하지 않는다. 구조 직후 속도는 1,000px/s이고 이후 정상 타격은 기존 전역 상한 1,380px/s를 따른다.

## 6. 게임당 2회 제한
세션의 `total`, `used`로 관리한다. 성공 발사 때만 정확히 한 번 차감하며 물리 발사 전에 체크포인트를 기록한다. 실패·취소·사라진 공에는 소비하지 않는다. 기록은 최근 20건으로 제한한다.

## 7. 좌우 공유
대포별 탄약을 만들지 않고 같은 RescueData를 참조한다. 왼쪽→왼쪽, 오른쪽→오른쪽, 왼쪽→오른쪽을 검사했다. 2회 소진 후 세 번째 위험 진입은 일반 아웃 경로를 따른다.

## 8. BALL SAVE
구조 감지를 drain 이전에 실행한다. 성공하면 공이 살아 있으므로 BALL SAVE와 무료 보호 횟수에 영향이 없다. 실패·소진 후 실제 아웃은 기존 BALL SAVE → 정상 손실/재발사 순서를 따른다. 실패/소진의 무료 보호 및 보호 없는 아웃의 에너지 20 차감·손실 1회를 검사했다.

## 9. 멀티볼·CORE STORM
현재 주 공 하나만 구조한다. 기존 주 공 승계를 유지하며 마지막 승계 공은 `allowPromotedLastBall` 설정을 따른다. 3/5/7/10개 동시 위험 진입, 승계 공 동일 객체, 10종 특수 공 질량/마찰 복원을 검사했다. 기존 CORE STORM·마법 회귀도 통과했다. 브라우저에서 CORE STORM 전체 전투를 장시간 플레이한 것은 아니다.

## 10. 모드·저장 규칙
| 모드 | 새 세션 | 이어하기·내부 전환 |
|---|---|---|
| 클래식 | 2회 | 새로고침·이어하기·판내 재시작에 사용량 유지 |
| 왕국 / 전쟁 | 2회 | 저장 복원에 유지 |
| 캠페인 | 새 스테이지마다 2회 | 진행 중 스테이지 복원에 유지 |
| 생존 / 보스 러시 / 로그라이크 | 도전 전체 2회 | 웨이브·보스·지역 전환에 재충전 없음 |
| 퍼즐 | 퍼즐 설정 | 기존 30개는 0회로 풀이 보존 |
| 샌드박스 | 기본 2회 | 설정에서 0~10회 변경 가능 |
| 온라인 | 플레이어마다 2회 | 서버 세션 권한·snapshot 동기화 |
| 커스텀 테이블 / 연습 | 비활성 | 기존 고유 규칙 유지 |

기존 저장에 rescue가 없으면 최초 로드에 기본 상태를 부여하고 저장한다. ID·총량·사용량·진행 상태·대상 공·포착 정보를 저장하고 정규화한다. 충전 중 복원은 손실 없이 이어간다. 브라우저 재시작 시 새 Matter 엔진의 공에 연결하므로 라이브 포착·발사에서의 동일 ID와 저장 재생성을 구분한다. 로컬 저장 파일 자체의 수동 변조 방어는 범위 밖이다. 온라인은 클라이언트 구조 명령을 받지 않고 서버에서 감지·차감한다.

## 11. HUD·그래픽·사운드
황금 금속 포신, 목재 프레임, 왕실 문장, 실제 방향 화살표와 충전 발광을 추가했다. `ROYAL RESCUE 왕실 구조 2 / 2`와 황금/어두운 충전 아이콘을 표시한다. 성공·소진 메시지는 실제 횟수를 따른다. 기존 AudioManager 합성음과 음소거·효과음 음량을 재사용하며 외부 음원은 추가하지 않았다. 섬광 감소·파티클 설정을 따른다. 390px 화면에서 HUD 한 줄 및 가로 넘침 없음 확인.

## 14. 문제·제한
초기 우측 궤적의 플리퍼 접근 부족은 최종 대칭 발사 설정으로 보정했다. 기존 건물·다른 공이 포구를 막으면 구조를 취소하므로 일반 아웃이 가능하다. 8개 지역은 같은 크기·레일 구조여서 공통 배치를 사용한다.

실제 인터넷의 두 사용자 대전에서 구조 장면 재현이나 지연·손실 장시간 시험은 수행하지 않았다. 온라인 구조는 실제 ServerSimulation 및 기존 WebSocket 회귀로 검증했다. 장시간 FPS/메모리 스트레스, 모든 건설 배치, 사람 난이도별 장기 생존 측정은 포함하지 않는다. 외부 공개 배포는 하지 않았다.
