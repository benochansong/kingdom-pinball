# PHASE 10 — 실제 온라인 대전 초기 버전

요청의 우선순위 1~3인 실제 두 플레이어의 온라인 전쟁과 서버 권한·저장·재접속을 구현했습니다. 협동 생존, IRON TITAN 협동 레이드, 빠른 일반 대전, 비공개 맵 공유도 제공합니다. 아래 미구현 항목을 포함한 전체 기획의 모든 기능이 완성된 것은 아닙니다.

## 1. 구현한 온라인 기능

게스트 접속, 참가 코드, 방 생성/입장, 두 명 준비, 빠른 일반 대전/취소, 실제 전쟁, 자원·건설·강화·병력·지휘·수리·속성·주문·멀티볼·STORM, 서버 승패/무승부/항복, 전적, 재접속, 전략 신호/음소거/신고입니다. 가짜 사용자와 AI 인간 위장은 없습니다.

## 2. 구조

기존 Vite/TypeScript/Phaser 싱글 플레이는 유지합니다. 온라인은 별도 Canvas HUD와 NetworkClient가 서버 스냅샷을 표시합니다. Node 24 + ws 서버는 기존 Matter 물리·EconomyManager·ArmyManager·WarManager·MagicManager를 재사용합니다. SQLite는 단일 서버 프로세스가 소유합니다.

## 3–4. 접속과 초대

`npm run multiplayer:dev` → 온라인 메뉴 → 게스트 접속 → 방 생성 → `KP-…` 코드 공유 → 상대 입장 → 둘 다 준비 완료. 자세한 한국어 설명은 [MULTIPLAYER_GUIDE.md](../MULTIPLAYER_GUIDE.md)에 있습니다. 현재 초대는 코드 방식입니다.

## 5–7. 1:1·물리·공용 전장

두 독립 PinballPhysics 인스턴스를 서버에서 240Hz로 전진시킵니다. 하나의 WarManager가 3개 공격로의 양 진영 전투를 계산합니다. 30Hz 게임 업데이트, 15Hz 스냅샷, 클라이언트의 70ms 보간 버퍼와 즉시 플리퍼 시각 반응을 사용합니다. 공의 보상 판정은 예측하지 않습니다. 완전한 클라이언트 물리 재시뮬레이션은 구현하지 않았습니다.

동일 자원·등급·마법 해금, 대칭 왕궁/방어시설, 동일 테이블로 시작합니다. 120초 준비, 양쪽 동의 조기 시작, 실시간 건설 12초, 개인 일시정지 없음입니다. 실제 왕궁 파괴로 승리하는 유료 병력 생산→자동 전투 테스트와 브라우저 항복 결과를 검증했습니다.

## 8. 자원·전투 검증

서버는 입력/요청만 받습니다. 타격·자원·위치·피해·승패·레이팅을 직접 주장하는 명령은 거부합니다. 실제 공 충돌이 생산/가속/충전을 발생시키며 전장 지원 목표는 1초 서버 쿨다운과 실제 살아 있는 대상을 사용합니다. 건설은 비용·해금·개수·영토·통로·목표물 충돌을 검사합니다. 협동 B의 수리 비용도 B 자원에서 지불합니다.

## 9. 협동 생존

독립 자원·건물·생산과 공용 아군/왕궁을 연결했습니다. 기존 seeded survivalWave를 확장해 두 공격로에서 다양한 병종을 보냅니다. 자원 전달, 공동 타격 생산/방어 콤보, 동시 멀티볼 보너스를 제공합니다. 자동 웨이브 보상이며 역할별 편성·선택 카드·모든 팀 콤보는 미구현입니다. 팀 지휘와 진형은 공유합니다.

## 10. 협동 보스

IRON TITAN 하나를 기존 BossManager로 구현했습니다. 실제 장갑, 체력, 단계, 충격파 예고와 보조 병력이 존재합니다. 보스 사망은 양쪽 팀 승리입니다. FROST QUEEN/MAGMA DRAGON/ARCHMAGE/DARK EMPEROR의 협동 변형은 미구현입니다.

## 11. 경쟁전과 순위

Elo 계산 함수는 테스트되어 있지만 공개 경쟁전, 지속 계정 인증, 배치전, 시즌과 레이팅 지급은 비활성/미구현입니다. 공개 UI는 서버 확정 일반전 승수만 보여줍니다. 공식 일일/주간 도전은 DB 확장용 스키마만 있고 공식 기록 제출은 허용하지 않습니다.

## 12. 재접속

256비트 무작위 세션 토큰을 검증하고 동일 경기의 전체 상태를 다시 보냅니다. 입력 sequence/ack는 서버에 남습니다. 연결이 끊기면 입력을 해제하고 전투를 계속합니다. PvP 유예 60초, 양쪽 끊김은 무승부 중단, 협동 한쪽 끊김은 남은 플레이어가 계속합니다. 서버 자체 재시작의 진행 경기 복원은 미지원입니다.

## 13. 맵 공유

Phase 8 제작기의 선택 테이블을 업로드하고 무작위 비공개 코드로 내려받아 새 로컬 프로젝트로 저장합니다. 서버의 256KiB 제한, 필드 whitelist, 객체·배치 검사를 거칩니다. 소유자 공유 중단과 신고 기록을 지원합니다. 공개 커뮤니티/검색/추천/즐겨찾기 및 사용자 맵 실시간 대전은 미구현입니다.

## 14. 부정 요청 방어

Origin allowlist, 16KiB WebSocket 메시지, 연결 인증 제한 시간, IP 요청 제한, 연결/방 상한, 입력 60/s 및 비입력 10/s token bucket, sequence 중복 제거, 방/소유권 검사, 송신 backpressure, HTTP 본문 제한과 timeout을 적용했습니다. 토큰은 URL이나 로그에 넣지 않습니다. Internet 보안 감사/침투시험이 완료된 서비스로 간주하지 않습니다.

## 15. 저장

SQLite WAL + 트랜잭션 + Match ID PRIMARY KEY로 중복 정산을 막습니다. profiles/sessions/matches/reports/tables와 도전용 예약 스키마를 분리합니다. sessions에는 토큰 해시만 기록합니다. DB 오류 시 확정 시뮬레이션을 재실행하지 않고 저장을 재시도하며 관리자 지표와 사용자 메시지를 남깁니다. 로컬 게임 저장은 온라인 권한에 사용하지 않습니다.

## 16. 주요 파일

- `server/server.ts`: HTTP/WebSocket, 인증, 로비, 매칭, 방 수명, 재접속, 제한, metrics
- `server/simulation.ts`: 두 테이블, 공용 전쟁, 서버 요청 검사, 협동, 스냅샷
- `server/persistence.ts`: 프로필/세션/결과/신고/맵 SQLite
- `src/network/`: 공유 프로토콜/목표물, 연결·보간, 온라인 UI
- `tests/online*.test.ts`, `scripts/online-performance.ts`: 실제 소켓·규칙·성능 검증
- `.env.example`, `Dockerfile.server`, `MULTIPLAYER_GUIDE.md`: 실행·운영 설정

## 17. 실제 검사

전체 회귀 236개 통과(19파일), 별도 기존 생성/soak 검사 2개 제외. 이후 자동 복귀 공의 재발사 검사를 추가하고 온라인·전쟁·마법 50개 검사를 다시 통과했습니다. 신규 온라인 검사는 총 13개로 실제 두 WebSocket 연결과 HTTP 맵 업로드, 서버 충돌 자원 생산, 유료 병력으로 왕궁 정복, 대칭 방어, 준비 보호, 건설/권한, 동시 멀티볼·STORM, 협동 소유권/자원/수리/진형, 보스 사망, 맵 whitelist, 보간 버퍼를 검사합니다.

브라우저 초기 PvP 검증: 실제 두 게스트, 코드 입장/준비, 발사 후 18회 유효 타격과 자원 증가, 병력 생산과 왕궁 피해, 같은 Match ID의 승리/패배를 확인했습니다. 추가 최종 검증 결과는 [VALIDATION.md](VALIDATION.md)에 기록합니다. 50/100/200/300ms는 실제 소켓 위의 애플리케이션 전달 지연 시험이며 OS 패킷 손실/실제 WAN 시험이 아닙니다.

## 18. 서버 실측

[원본 JSON](online-performance.json): 두 테이블 각각 최대 10공, 방당 초기 40기, 6초 가상 전투와 양쪽 15Hz JSON 생성. 전체 방 업데이트 P95는 1방5.51ms / 5방16.77ms / 10방27.54ms, P99는 12.17/28.91/45.66ms였습니다. 10방 일부 프레임은 33.3ms 예산 초과입니다. 기본 상한은 5방이며 실환경 재측정이 필요합니다. 20방 미측정, 브라우저 FPS·인터넷 동접 보장이 아닙니다.

30분 가상 서버 세션은 약 11초 CPU 실행 후 시간 제한 결과까지 완료했습니다. 최대 물리31개/테이블, 병력26기. 자원이 자연스럽게 소진되는 반복 생산 시나리오입니다. 실제 30분 벽시계 안정성, GC 이후 메모리 누수 분석, 서버 장애 복구 시험은 미완료입니다.

## 19. 기존 기능

1~9단계 회귀를 유지하고 온라인은 별도 화면/저장을 사용합니다. 기존 MagicManager에는 플레이어가 조종하는 적 좌석 옵션, WarManager에는 명시적 양 진영 명령과 협동 비용 지불자, ArmyManager에는 협동 인구 소유 필터만 선택적으로 확장했습니다. 기본 싱글 플레이 동작은 기존 경로입니다.

## 20–21. 배포와 운영 부담

정적 클라이언트와 지속 Node 서버를 분리합니다. HTTPS/WSS 프록시, 영구 SQLite 볼륨, 백업, 모니터링, 신고 검토가 필요합니다. 실제 클라우드 서비스/유료 계정/DNS 변경은 하지 않았습니다. Dockerfile은 제공했지만 컨테이너 배포는 검증하지 않았습니다. 현재 공급자가 정해져 있지 않으므로 월 비용을 지어내지 않고 실제 공급자의 서버·디스크·트래픽 요금 확인 방법을 안내했습니다.

## 22–23. 남은 범위와 Phase 11

다른 PC/WAN 시험, 장시간 실시간 soak, 풀 클라이언트 예측/재조정, 대역폭 delta snapshots, 온라인 화면의 Phase 9 수준 아트·오디오 통합, 전체 지역/장군/역할 선택, 추가 협동 보스·콤보, 보상 선택, 안전한 지속 계정 인증, 공개 경쟁전 운영, 공식 도전 검증, 공개 커뮤니티, 관전, 완전한 리플레이, 다중 서버와 재시작 복원은 남아 있습니다. 서버 입력/중요 이벤트의 완전한 리플레이 로그도 아직 저장하지 않습니다. 무검증 로컬 기록을 경쟁 기록으로 올리는 우회는 제공하지 않습니다.

구현 참고: [ws 공식 API](https://github.com/websockets/ws/blob/master/doc/ws.md), [Node SQLite API](https://nodejs.org/api/sqlite.html).
