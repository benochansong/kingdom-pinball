# PHASE 8 — Game Modes & Replayability

## 1. 플레이 가능한 모드

기존 캠페인·왕국 발전·왕국 전쟁·클래식·훈련에 생존, 샌드박스, 보스 러시, 퍼즐, 로그라이크, 테이블 제작기, 일일·주간 도전, 사용자 정의 전쟁, AI 관전을 추가했다. 하나의 GameStateManager와 전쟁 엔진을 공유하지만 현재 모드의 SessionExtension 하나만 시간을 진행한다. 보상/경로 선택 중에는 다른 대화상자를 닫아도 시뮬레이션이 진행되지 않는다.

## 2. 진입 및 조작

메인 화면의 캠페인 계속, 왕국 전쟁, 생존, 샌드박스 또는 GAME MODES에서 시작한다. 나머지 모드와 기존 훈련은 모드 선택 화면에 있다. A/D 또는 좌우 화살표, Space 충전/발사, B 건설, U 군대, L 전쟁 지휘, Tab 마법, Esc 일시정지 등의 기존 조작을 유지한다. 모드 HUD에서 보상, 다음 웨이브, 경로, 초기화, 저장 후 메뉴를 조작한다. 프로필의 실제 완료 이력으로 최근/추천 모드를 표시한다.

## 3. 생존

경제·요새·군사·마법·균형 시작 상태, 8지역, 5난이도, 장군·장비·특수 공 선택을 지원한다. 준비 시간이 끝나거나 ‘지금 시작’을 누르면 웨이브가 시작된다. 5웨이브마다 지휘관, 10웨이브마다 보스가 등장하며 20 얼음, 30 화산, 40 비전, 50 이후 암흑 보스를 사용한다. 이후 증가량은 등급 5와 웨이브 대기열 100에서 제한한다. 적을 일정 간격으로 배치하고 현재 웨이브를 모두 해결해야 보상으로 넘어간다. 3개 보상 중 하나를 정확히 한 번 받고 20초 재정비 또는 즉시 다음 웨이브를 선택한다. 자원·회복·병력·마법·상한 있는 강화 보상을 제공한다. 결과는 조건별 로컬 기록이며 캠페인 자원으로 환전하지 않는다.

## 4. 샌드박스

무료/일반 자원, 생산·비용·저장·인구·훈련, AI·이동·침공·파괴·왕궁 피해·진영 무적, 마법·마나·충전·쿨다운·종료 조건을 별도 인스턴스에서 제어한다. 시설 건설, 병종/진영/수량/등급/연구/진형 생성, 8보스 소환, 특수 공·멀티볼·STORM을 실험할 수 있다. 중력·질량·탄성·마찰·최대 속도·플리퍼·범퍼·가속·감속·바람·공 개수는 수치 범위를 검사한다. 초기화와 프로젝트 10슬롯 저장/불러오기를 지원하며 점유 슬롯 덮어쓰기는 화면에서 확인한다. 1×/2×와 공을 제거하는 군사 실험용 4×를 제공한다. 경쟁 업적·캠페인 성장 보상은 없다.

## 5. 보스 러시

8보스를 연속 공략한다. 일반·시드 고정 무작위 순서·원소·공성·전설 변형을 구분한다. 왕궁 HP, 자원, 시설, 생존 병력을 유지한다. 지역 전환 시 장치와 겹치는 시설을 안전 위치로 이동하고 불가능하면 지불 자원을 반환한다. 보스 처치 사이에 보상을 선택한다. 각 보스 시간, 총 시간, 피해, 병력/마법 사용과 왕관 등급을 기록한다. 전설은 강화 보스와 빠른 첫 공격 예고를 사용한다.

## 6. 퍼즐

BEGINNER/ADVANCED/MASTER 각 10개, 총 30개다. 조준, 순차 목표, 벽 반사, 배치한 반사판의 실제 접촉, 포털 통과, 화염 속성 타격, 포로 해방 후 안전지대 이동, 단일 공 제한을 구현했다. 3단계 힌트와 초기화, 제한 시간/공, 별 3개 평가가 있다. 순차 목표는 타격 후 다른 위치로 이동한다. 반사판은 발사 전 제한된 위치에서 각도를 선택한다. 자유 건설 퍼즐이나 임의 자동 풀이 기능은 아니다. 퍼즐 ‘계속’은 같은 문제의 새 시도로 시작하며 기존 최고 별은 유지한다.

`tests/fixtures/puzzle-replays.json`은 실제 GameStateManager, 충돌, 회복, 마법 속성, 플리퍼 입력으로 성공하는 개발용 재현 입력이다. 목표 달성 플래그나 충돌 이벤트를 주입하지 않는다. 생성기는 개발 검증용이며 플레이어 화면에서 자동 재생하지 않는다.

## 7. 로그라이크

3막 × 5행, 총 15노드를 선택해 진행한다. 일반 행은 2갈래, 각 막 마지막은 보스로 연결되며 막힌 경로 없이 생성된다. 전투·정예·자원·시장·수리·보물·성소·룬 타격 퍼즐·보스 노드가 있다. 안전/정예/저주 조건과 비용을 표시한다. 강화 24종(각 최대 3중첩), 유물 12종(중복 없음), 5희귀도 가중 추첨이다. 유물은 Golden Crown, Iron Heart, Frost Mirror, Dragon Ember, Royal Standard, Arcane Clock, Twin Core, Phantom Rune, Merchant Seal, Storm Relic, Siege Hammer, Living Crystal이다. 실제 생산·전투·회복·충전·쿨다운·임시 공·관통·거래에 연결했다. 효과는 이번 원정에만 남는다.

## 8. 제작기

그리드에서 선택/드래그, 수치 위치/크기/회전 편집, New/Open/Save/Test/Validate/Export/Import를 제공한다. 범퍼·벽·반사판·시설·포털·타겟·병력·보스·장식/도달 구역·바람·가속·감속을 배치한다. 점수/자원/전쟁/생존/보스/퍼즐 규칙과 점수·생산·시간·타격·처치·보스·구역 목표를 선택한다. 7템플릿과 테이블 20개 로컬 저장을 지원한다.

경계·발사로·플리퍼 여백, 충돌 겹침, 포털 연결과 출구, 생성 위치, 목표 조건, 공 통과 경로를 검사한다. 오류는 테스트/저장을 차단한다. 정적 검사만으로 ‘풀 수 있음’을 주장하지 않는다. 직접 테스트에서 목표 달성 후에만 동일한 내용의 일반 Play를 허용하고, 편집/가져오기 시 검증을 다시 요구한다. JSON은 256KB/80오브젝트/버전1/유한 수치/허용 목록으로 제한한다. 알 수 없는 필드는 실행하거나 저장하지 않는다. 내보내기 확장자는 `.kingdompinball.json`이다. 파일의 검증 표시는 신뢰하지 않는다.

## 9. 일일·주간

UTC 날짜, ISO 주차, 버전 0.8.0으로 규칙과 시드를 결정한다. 다음 갱신은 로컬 시각으로 표시한다. 요새·마법·경제·공성·멀티볼·보스 6템플릿이며 실제 생산/주문/분열/보스/방어/시설 파괴 목표를 판정한다. 마법 목표에는 시설·연구·마력·초기 충전을 준비한다. 같은 기간의 시드와 목표는 동일하다. 브라우저 로컬 기록으로, 서버 검증이나 공식 순위가 아니다. 놓친 날짜에 패널티가 없다.

## 10. 저장 분리와 기록

`kingdom-pinball:mode:v1:<mode>`, `kingdom-pinball:sandbox:v1:<0..9>`, `kingdom-pinball:tables:v1`, `kingdom-pinball:profile:v1`을 사용한다. 생존·러시·로그라이크 등 현재 세션과 최근 30개 결과를 모드별로 저장한다. 보상 ID, 노드 완료, 종료 기록 ID로 중복 적용을 막는다. 장시간 모드는 공의 비행 궤적 대신 기존 전쟁의 지불된 안전 체크포인트로 복귀한다. 다른 창에서 변경한 키의 쓰기는 중단한다. 테이블 검증 지문은 원본을 수정하면 달라진다.

프로필은 이름/문장, 플레이 이력, 별 기록, 칭호 13종의 해금 조건과 기본 칭호, 업적, 외형 9범주 × 3색 계열을 저장한다. 스피어·플리퍼·범퍼·깃발·왕궁·문장·마법·테두리·결과 배경의 색상 장식에 적용한다. 외형 보상에는 능력치가 없다. 서로 다른 모드의 점수를 하나의 순위로 합산하지 않는다.

## 11. 기존 기능과 연결

캠페인 저장 키와 진행, 기존 클래식 최고 점수와 왕국 경제·전쟁 기록은 별개다. 기존 AI를 진영 매개변수로 확장해 관전 양쪽에 재사용했다. 실제 자원 생산·훈련·침공을 사용하며 관전은 보상/경쟁 기록에서 제외한다. 사용자 정의 전쟁은 noMagic/allMagic/limitedArmy/fortress/economy/rapid/long/oneCore/random 변형과 standard를 지원한다. 환경 타겟이 보너스 상자 해금 상태에 걸리던 문제와 마법 없는 전쟁의 시설 피해 처리도 수정했다.

## 12. 파일

`src/modes/`의 공통 관리자/저장/전투 어댑터 및 모드별 규칙, `src/config/{modes,puzzles,roguelike,profile}.ts`, `src/ui/{ModeUI,TableCreatorUI}.ts`, `src/modes.css`, 모드 렌더러를 추가했다. 게임 루프에는 모드 시간 정지와 사용자 테이블 구성 훅을 추가했다. 기존 AI·마법·렌더러의 필요한 부분만 공유했다.

## 13. 검증

`npm install`, `npm run dev`, `npm run typecheck`, `npm run build`, `npm test`로 실행한다. 별도 긴 검사는 PowerShell에서 `$env:MODE_SOAK='1'; npx vitest run tests/mode-soak.test.ts`이다. 퍼즐 입력 재생 검사는 일반 테스트에 포함된다. 재탐색은 `$env:GENERATE_PUZZLES='1'; npx vitest run tests/puzzle-generation.test.ts`이며 테스트 입력 파일을 갱신한다. 결과 수와 브라우저 확인은 최종 검사 후 VALIDATION.md에 기록한다.

## 14. 장시간 및 성능

`docs/mode-soak.json`: 게임 시간 **3,600.146초**, 웨이브 **75**, 보상 **74**, 최대 저장 병력 **28**, 대기열 **100**, Matter body **44**, 세션 JSON **33,853바이트**. 실행 시간 약 **81.6초**. 왕궁 보호, 5초마다 테스트 피해로 적 제거, 발사대의 정지 공을 사용해 수명주기/큐/반복 보상을 검사했다. 수동 60분 플레이, 승률 밸런스 또는 60FPS 증거가 아니다. 별도로 1~1,000웨이브 생성의 대기열·등급 상한을 검사한다. Phase 7의 대규모 렌더링 성능 제한은 해결되었다고 주장하지 않는다.

## 15. 제한과 추가 검증

제작기의 크기는 600×900이며 외곽 레일·발사대·플리퍼·드레인은 안전상 고정이다. 프리셋은 배경/규칙을 바꾸며 임의 테이블 크기, 플리퍼 추가/이동은 지원하지 않는다. 자동 경로 검사는 보수적인 정적 검사이고 최종 도달 가능성에는 직접 테스트가 필요하다. 퍼즐은 8종 규칙의 단계별 변형이며 30개의 완전히 다른 미술 테마는 아니다. 각 난이도/장군/유물 조합의 장시간 사람 플레이 승률, 저사양 실기기, 브라우저 간 성능, 오디오 청감은 미검증이다. 온라인 계정·공유 서버·전역 순위·결제는 구현하지 않았다.

## 16. Phase 9 연결

다음 단계에서는 새 규칙을 더 늘리기보다 기존 모드의 가독성, 디오라마 테이블, 건물/병력 애니메이션, 지역 조명, 보스·마법 연출, 상황별 오디오, 품질/접근성 설정을 개선한다. 물리 규칙과 저장 호환을 보호하고, 성능 결과는 CPU 시뮬레이션과 실제 브라우저 렌더링을 분리해서 보고한다.
